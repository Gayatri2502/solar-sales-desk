# Known limitations and local audits

## Before live customer use
Supabase project/JWT authentication, account-specific hosted AI availability and paid provider responses have not been exercised without credentials. Database RLS and CAS semantics are tested locally using Postgres/PGlite. Complete staging tenant tests, real two-client stock races, CPU profiling, backups and browser printing on the customer's system before operating live.

The app is a usable demo and a pilot implementation, not a proven high-volume service. One aggregate per tenant simplifies transactional workflows but has growing read/write cost. No realtime sync/polling: refresh to see other staff's updates; commands fetch the latest state and reject/retry conflicts. Normalize/paginate before large sustained workloads. Operator CLI restores require trusted backups and a maintenance window; run a live restore rehearsal.

INR is the only implemented currency. Timezone and tax settings are configurable. Quote tax is a configurable single rate per line plus separate delivery tax, not a GST accounting engine; no CGST/SGST/IGST allocation or legal tax guidance is implemented. Business must determine whether that document structure meets its requirements. Quantities have three decimal places, amounts two; no exchange-rate, payment reconciliation, credit-note, returns or accounting workflow.

Technical attributes are reviewed text, with deterministic category and explicit wattage filtering plus catalogue word/spec matching and staff selection. Compatibility is never verified by AI. Manufacturer documents and structured category-specific electrical filters may be needed before recommending systems. The demo parser extracts only explicit quantity-unit patterns; real AI output is still reviewed and schema-validated.

Product CSV imports add new SKUs only; duplicates are row errors, never silently overwritten. Existing physical stock changes require a reason through stock adjustment. No ERP feed. Quotes reserve stock only on order conversion, not at approval. Stock shortages can be acknowledged at approval, but conversion cannot oversell. Cancellation after dispatch and returns require an operator-reviewed process outside this MVP. A cancelled order's old quote cannot create a second order; staff can create a new revision or new enquiry.

One Auth account belongs to one business in this MVP; cross-business account switching is not implemented. Admin-created users, admin password reset and authenticated self-change avoid required paid SMTP. Password reset is audited; no SMS or automated email recovery is available. Auth account deletion after tenant deletion requires operator review. Documents are never uploaded; no server-side document archive or retention policy is silently invented.

Application/provider budgets are estimates; failed provider calls may still cost money and are reserved conservatively. Cached extraction is opportunistically purged after 24h; schedule maintenance SQL for strict expiry during inactivity. No hosted call made in this build. Optional local models and Gemini adapter were omitted rather than adding another unverified runtime.

## Dark-pattern audit
Scope: full source, UI copy, billing configuration and documentation. Method: local source/copy review using the retrieved pattern catalog. No dark patterns detected from the local codebase. That is a good sign.

Evidence: demo banner explicitly states synthetic/local data; manual subscription record explicitly denies payment verification; fee, renewal, allowance and estimated spending ceiling are visible; no payment gateway, automatic renewal charge, free/unlimited claim, fake testimonial, timer, or automatic customer message exists. Cancelling the manual subscription record does not hide data export/manual entry. Stock shortage flags derive from catalogue snapshots and are labeled, not scarcity marketing. Static analysis cannot rule out runtime or operator behavior outside this repository.

## Accessibility and React review
Uses semantic links/buttons/table headers, labeled form controls, visible focus, skip link, Radix dialog titles/descriptions/focus containment and Escape handling, textual status/warnings, and internally scrollable tables. Narrow layout was inspected in the app browser; overflow fixes applied. Automated Playwright+axe browser suite is supplied but Chromium launch is blocked by this environment's macOS sandbox. This is not a claim of full WCAG conformance. See test results for rendered DOM checks and the actual React Doctor findings.

Order invoices now support draft, sales submission, admin approval and a server-only email queue. Email configuration remains disabled/unverified with real recipients; demo does not transmit. Email includes the invoice body, with local approved print-to-PDF; no PDF email attachment or WhatsApp invoice delivery. Accepted-by-provider is distinct from customer delivery/payment. Issued-invoice corrections/credit notes, bounce webhooks and verification of business-specific invoice requirements remain outside the pilot. See INVOICES.md for retry limits, restore quarantine and activation checks.

Public landing, authentication forms and guarded live access are implemented. Firebase Auth and core trusted Worker storage are now implemented behind explicit configuration. Hosted Firebase tests require the dedicated server credential. Firebase provider dispatch, AI/account administration, invoice email, export/deletion and restore code are now implemented and locally tested. Actual hosted workflows remain pending account credentials and release checks; the default local setup still uses synthetic data and the alternate live backend is Supabase. Meta WhatsApp and Vapi adapters require real credentials and staging verification. Contact automation is initially bound to one pilot business, processes two due calls per five-minute run, and needs manual reconciliation for unknown acceptance or missing completion reports. Public subscription amounts and operator legal/contact details are pending; prices are negotiated rather than invented. These constraints prevent declaring the application production ready today.
